你现在需要帮我完成一个本地网页制作任务。

## 任务目标

把当前指定文件夹中的**所有图片和音乐文件**制作成一个可以直接用浏览器打开的 `HTML` 页面。

### 核心要求

1. **扫描当前文件夹**

   * 自动读取当前文件夹中的文件。
   * 自动识别图片文件，例如：

     * `.jpg`
     * `.jpeg`
     * `.png`
     * `.webp`
     * `.gif`
     * `.bmp`
   * 自动识别音频文件，例如：

     * `.mp3`
     * `.wav`
     * `.m4a`
     * `.ogg`
     * `.aac`
   * 不要让我手动填写每张图片的文件名。

2. **生成 HTML**

   * 在当前文件夹生成一个 `index.html`。
   * HTML 必须使用相对路径引用当前文件夹中的图片和音乐。
   * 不要把图片转换成 Base64，除非确实有必要。
   * 不要把音频转换成 Base64。
   * 最终的 `index.html` 应该可以直接双击打开。

3. **图片展示**

   * 将文件夹里的图片全部展示出来。
   * 图片按照文件名或自然排序排列。
   * 页面需要有较好的视觉效果，不要只是简单的 `<img>` 标签堆在一起。
   * 图片可以采用响应式网格 / Gallery / Slideshow 等形式。
   * 点击图片可以放大查看。
   * 图片比例不要被强行拉伸。
   * 页面需要适配电脑和手机屏幕。

4. **音乐播放**

   * 使用文件夹中的音频文件作为背景音乐。
   * 默认使用第一个识别到的音频文件。
   * 如果文件夹里有多个音乐文件，可以做成音乐列表或播放队列。
   * 提供：

     * 播放 / 暂停
     * 上一首
     * 下一首
     * 音量控制
     * 进度条
     * 当前音乐名称
   * 如果浏览器允许，进入页面后尝试自动播放。
   * 如果浏览器阻止自动播放，不要报错，而是显示一个明显的“点击播放音乐”按钮。
   * 不要通过奇怪的方式绕过浏览器的自动播放安全策略。

5. **图片与音乐的关系**

   * 如果图片数量和音乐数量没有对应关系，不要强行一一匹配。
   * 音乐作为整个页面的背景音乐即可。
   * 用户切换图片时音乐可以继续播放，不要重新加载音乐。

## UI / 视觉要求

做成一个真正完成度较高的网页，而不是 Demo。

要求：

* 简洁
* 现代
* 有层次感
* 不要廉价的模板感
* 不要大面积纯蓝色
* 不要过度使用渐变
* 不要出现“AI generated”“Made with Claude”等无关文字
* 页面主体突出图片
* 音乐控制器可以固定在底部
* 使用 CSS 动画做一些细微的过渡效果
* 图片加载时可以有淡入效果
* 背景可以根据图片整体风格设计，但不要影响图片观看

## 技术要求

优先使用：

* HTML
* CSS
* 原生 JavaScript

除非确实有必要，否则不要引入 React、Vue、Node.js 等复杂框架。

要求：

* 所有资源使用相对路径。
* 不依赖网络 CDN。
* 不需要联网才能运行。
* 不要使用外部字体、外部图片或外部 API。
* 最终页面应该是一个可以离线运行的本地 HTML。

## 文件处理

请先检查当前目录中的实际文件，不要假设文件名。

执行以下流程：

1. 查看当前目录。
2. 找出所有图片。
3. 找出所有音频。
4. 判断哪些文件可以被浏览器直接支持。
5. 根据实际文件生成 HTML。
6. 如果图片或音频文件名包含中文、空格或特殊字符，确保 HTML 中的路径能够正常工作。
7. 生成 `index.html`。
8. 检查 HTML 中所有资源路径是否正确。
9. 如果可以，在本地进行基本测试，确保没有明显的 HTML / JS 错误。

## 重要

不要只告诉我应该怎么做。

请直接在当前文件夹中完成文件创建和修改。

完成后告诉我：

* 找到了多少张图片
* 找到了多少个音频文件
* 生成的 HTML 文件叫什么
* 如何打开它
